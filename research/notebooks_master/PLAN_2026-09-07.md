## 3. 系列拆分原则

每赛按适用性拆成以下模块。编号不是强制流水线，读者可以单独使用其中一篇。

| 模块 | 独立读者问题 | 必须交付 |
|---|---|---|
| A. 数据审计 | 数据实际长什么样，哪些地方容易读错？ | schema/质量统计、有效样本可视化、检查函数 |
| B. 验证与评价 | 如何评价才不自欺？ | split 或 metric 工具、边界测试、对照结果 |
| C. 轻量基线 | 最小成本能建立什么参照？ | 独立可运行 baseline、资源与结果记录 |
| D. 专题消融 | 某个具体决策究竟有没有帮助？ | 控制变量、多个条件、负结果和适用边界 |
| E. 工程工具 | 如何更快、更稳定地开展实验？ | 实测的读取器、缓存、可视化或诊断工具 |
| F. 综合分析 | 多局/多实验出现什么稳定规律？ | 分层统计、样本口径、反例和不确定性 |

不拆分：把同一份 EDA 分成缺失值篇、相关性篇、画图篇；只改随机 seed 或模型名字重发；同一 Notebook 的小版本更新换 slug。独立篇必须回答不同问题并提供不同可用成果。

共用读取器和辅助函数可以复用，但公开 Notebook 不能依赖私有仓库、未经审核的外部脚本或上一个 Notebook 的手动隐藏状态。每篇必须具备从官方输入独立启动的路径。

## 4. 重点限时赛：每赛 5 篇

以下英文标题均为工作标题。技术选题是待验证假设，不是已观察到的错误、已测成绩或已存在的字段。代码实现前核对 schema、规则与同赛现有作品；已被覆盖的问题需要实质增量，否则合并或撤销。

### EV：Predicting Electric Vehicle Purchases

来源：https://www.kaggle.com/competitions/playground-series-s6e9
已核实：ROC-AUC；2026-09-30 23:59 UTC 结束，北京时间 10-01 07:59；不授予 Competition 奖牌，不影响按 Code 规则评估相关公开 Notebook。

- `EV-A` **Data Audit and Distribution Checks**：缺失、类别、重复记录、目标分布和 train/test 差异；交付可复用审计表。目标比率只对公开标注集统计。
- `EV-B` **Validation Under Duplicate and Group Structure**：实际发现重复/群组结构后比较切分；若不存在，则验证假设并改为数据支持的稳定性问题，不凭空造组。
- `EV-C` **A Reproducible CPU Baseline**：使用成熟库建立朴素模型与一个树模型，所有预处理在 fold 内拟合，报告同一切分下的 AUC、时长和内存。
- `EV-D` **Feature Ablations Without Leaderboard Guessing**：针对审计形成的 2～3 个特征假设进行单因素消融，保留无提升和反向结果；不调测试标签，不用 LB 反推标签。
- `EV-E` **OOF Diagnostics and Model Disagreement**：只使用合法获得、来源和切分一致的 OOF；分析错误分组、预测相关性和简单融合的稳定性。概率校准与 AUC 改善分开，不预设校准会涨 AUC。

依赖：A -> B -> C -> D/E。首发优先 A 或 C，但 B 的切分审核必须先于对模型结果作解释。

### RSNA：Knee Abnormality Detection

来源：https://www.kaggle.com/competitions/rsna-knee-abnormality-detection
已核实：12 标签 macro ROC-AUC；10-15 23:59 UTC 入场截止，10-22 23:59 UTC 最终截止。完整 Rules 与数据发布限制仍需实施前核查。

- `RSNA-A` **Study, Series and Label Audit**：确认真实文件层级、模态与标签可用性，记录无法读取或缺失项；不导出个人身份信息。
- `RSNA-B` **Leakage-Safe Multilabel Validation**：根据实际 patient/study/site 等可用且合法字段确定独立单位；交付分组划分和类别缺失检查，处理单类别 fold 的 AUC 不可定义情况。
- `RSNA-C` **A Small-Sample Imaging Baseline**：授权数据上用小子集和轻量模型做端到端 smoke test；写清样本覆盖，不把小样本结果称为全量性能。
- `RSNA-D` **What Information Is Available at Inference?**：训练与推理模态可用性矩阵、潜在标签泄漏审计；只有规则和测试契约允许的模态才进入模型，不假设报告在推理时可用。
- `RSNA-E` **Low-Memory Loading and Cache Benchmarks**：同一合法样本集测试 2～3 种读取/缓存配置，报告内存、首次与重复加载时间，验证数据等价；不打包再发布原始医学数据。

依赖：A/B -> C；A -> D/E。GPU 预算未批准时先做 A、B、D 与 CPU 数据加载测试。

### BIO：Biohub - Cell Tracking During Development

来源：https://www.kaggle.com/competitions/biohub-cell-tracking-during-development
本日目录显示 23 days to go；准确入场/提交时间待查。

- `BIO-A` **Dataset Geometry and Annotation Audit**：核查维度、单位、坐标、帧索引、标注边界；交付检查函数。
- `BIO-B` **A Track and Annotation Viewer**：合法样本上的时空关联可视化，证明坐标变换与图像/标注对齐；不要把某个切片当作完整体数据。

- `BIO-E` **Resolution and Runtime Trade-offs**：控制序列/帧集合，比较分辨率或批量设置的精度与资源消耗，并记录难例和失败。

短截止项目不保证能在截止前形成 3 篇可靠作品。先发布具备独立价值且已通过审核的篇目，其余保留候选；如果比赛已结束，重新确认数据访问和公开规则，明确标为 retrospective，而不是伪装成活动赛首发。

### 10.2 12 周滚动产能

假设每周投入 25～35 小时；这是建议预算，尚未授权付费算力。初期每个独立 Notebook 按约 4～6 小时估算，复杂赛可能显著更长。保留至少 25% 时间给核验、维护和评论处理，依据首两周真实耗时重新排期。

| 阶段 | 新作品预算 | 主要动作 |
|---|---|---|
| Weeks 1–2 | 8～10 篇 | 首批重点赛 A/B/C，短截止赛初探；建立审核模板 |
| Weeks 3–6 | 16～20 篇 | 重点赛系列展开，社区赛逐项补齐，先完成第一轮广泛覆盖 |
| Weeks 7–10 | 16～20 篇 | 各赛第二/三篇、长期练习赛，按真实复用需求调整深挖 |
| Weeks 11–12 | 4～8 篇 | 填补高价值缺口，重点维护 10～15 个成熟候选作品 |
| 合计 | 44～58 篇 | 仅发布通过门槛者，不为追数字放宽审核 |

112 个候选按每周约 4～5 篇计算，需要约 23～28 个生产周，且还未计未发现赛事和复杂阻塞；不能声称 12 周内全部完成，更不能声称那时所有比赛仍在进行。若必须全部在各自截止前完成，需要增加人员/算力并重新核准预算，或缩小范围。

“所有当前赛事”以 2026-09-07 cohort 冻结，完成或阻塞状态永久保留；后来新开的赛事进入独立 new-cohort 队列，避免无限加任务导致无法完成。每周更新仍活动/已结束状态，旧赛可转赛后研究，不从台账悄悄删除。

工作中任务上限：同时开发最多 3 篇、等待审核最多 5 篇。发布目标每周约 4～5 篇，不短时间批量倾倒同质内容。同一比赛相邻篇通常错开 2～4 天以吸收反馈，特殊截止情况以质量为前提调整；这是内部节奏，不是 Kaggle 限制。

### 10.3 运行预算

- 表格/文本初探优先 CPU，单次完整运行目标 15～30 分钟以内；超过时先评估数据抽样和问题范围。
- 图像/时序优先 metadata 和有说明的抽样；需要 GPU 的 baseline 先用一个小预算验证可行性，再由负责人批准扩容。
- 不默认下载 TB 级数据，不默认租 GPU，不默认调用付费 API，不把系统全部剩余资源占满。
- 多因素实验先做单因素筛查，再对少数候选扩大样本。时间/显存/数据访问约束不能靠伪造结果解决。
- 周报记录实际人时、CPU/GPU 小时、存储、失败次数和待处理问题，用真实产能调整而非补发低质量作品。

## 11. 每篇发布门槛

1. 标题具体、诚实，默认英文以便国际社区使用。主标题可用 `Competition | Reader Problem`，系列关系在正文中说明，不以编号代替可检索用途。
2. 首屏说明问题、交付物、数据版本、运行环境和范围，避免无实测的宏大宣言；没有 LB 结果就不写 LB 标题。
3. 图表必须来自实际运行，抽样说明包含 seed、单位、数量与覆盖率；不能把局部样本称为全量结论。
4. 数据质量/可视化篇不强制训练；实验篇必须有基线、主指标、对照及失败案例，不能只给最好一次。
5. 明确训练、验证、OOF、Public LB、Private LB、模拟局分数的区别。预处理不能在验证集拟合，阈值/规则不能用保留评估集挑选。
6. 声称稳定提升前，在适当的独立单位和多个 split/seed/任务上复验。固定 seed 不是稳定性的证明；诊断实验不必夸大为泛化结论。
7. 干净 Kaggle session 完整执行成功并保存输出；记录 Python/库/输入版本、硬件、时长、内存、exit status 和运行链接。需要外部环境时清楚区分“Notebook 内可重现”和“外部前置实验”。
8. 合法调用已验证的第三方库；记录参考 URL、作者、许可证和改动；fork 显著署名，不将他人代码包装成原创。
9. 检查输出、附件和日志中的密钥、私有路径、个人信息、受限样本及团队资产。输入挂载权限不等于输出再分发许可。
10. `RUN_VERIFIED` 后还必须经过内容与合规审核。发布批准绑定具体文件哈希、Notebook 版本和公开输出；有实质内容变更要重新审核。

失败结果有明确问题、可靠方法和复用价值时可以发布；运行失败的空壳、未验证假设、仅复制官方说明的作品不得标为完成。

## 12. 规则与数据风险

- [EV Rules](https://www.kaggle.com/competitions/playground-series-s6e9/rules) 同时出现 CC BY 4.0 与禁止向未参赛者再分发 Competition Data 的 Data Security 文本。不能自行选择有利条款；对原始行、导出文件或公开样例有疑义时要求官方澄清。
- RSNA Overview 可见不代表原图、报告或派生数据可自由转载；实施前核对完整规则、隐私和输出边界。不得进行身份识别或推断个人敏感信息。
- 某些社区赛可能限制资格、工具、外部数据或公开分享；目录显示 Active 不是最终许可证明。
- 无明确代码许可证时标记 UNVERIFIED，不复制执行或公开再分发；解释方法与独立实现也必须尊重比赛规则和可见信息边界。
- 多 Notebook 只用于公开知识分享，不多账户、不复制刷票、不互赞、不向他人索赞、不跨讨论区铺链接。Copy & Edit 是真实使用的信号，不是可操纵的任务配额。
- 发布 Notebook 不等于 submission。不要自动点击 Submit、选择最终提交、创建新账户、接受未知条款或改变数据权限。
